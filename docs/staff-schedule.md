# 직원 근무표

- 직원: `/staff/` (관리자가 발급한 개인 링크로 최초 접속)
- 관리자: `/staff/admin/` (근무표 전용 비밀번호 또는 사이트 소유자 관리자 계정)
- 구성원을 **아토스 직원**(최대 3명)과 **스태프**로 구분한다. 먼저 아토스 직원 3명을 등록하고, 각자의 개인 링크를 직접 전달한다. 기존 구성원은 기본적으로 스태프로 분류되며 관리 화면에서 구분을 변경할 수 있다. 신청 중이거나 확정된 주가 있으면 직원 구분 변경은 제한된다.
- 아토스 직원은 매월 25일까지 다음 달에 실제 근무할 날짜를 입력한다. 반복 요일 또는 개별 날짜로 선택하며, 근무가 없어도 빈 날짜로 제출한다. 25일은 안내 기준이며 자동 제출 차단은 하지 않는다.
- 관리자는 월간 달력에서 날짜와 근무자 이름을 중심으로 확인한다. 토요일은 파랑, 일요일은 빨강이다. 점선 이름은 확정 전 배정이며, 신청 중인 빈자리만 모집 인원으로 표시한다. 날짜를 누르면 달력 아래 배정 메뉴가 열리고 해당 날짜의 필요 인원과 배정을 편집한다. 같은 주의 다른 날짜로 이동해도 작성 내용은 유지되며, 다른 주나 달로 이동할 때는 저장하지 않은 변경을 확인한다. 월간 현황은 선택한 달의 직원 입력, 신청 중인 날짜, 앞으로의 미배정 자리, 공개 중인 확정 근무일을 집계한다.
- 선택한 날짜의 달력 아래 **스태프 신청 · 주간 확정**에서 직원 3명의 입력 현황과 자동 반영된 근무일을 확인한다. 신청 열기·닫기, 근무 시간 변경, 최종 확정은 표시된 한 주 전체에 적용된다. 해당 주에 걸친 모든 달의 입력을 3명 모두 완료해야 **스태프 신청 열기**가 가능하다. 월 경계 주는 양쪽 달을 모두 입력해야 한다. 모든 배정·주간 확정·구성원 관리·변경 요청·월간 현황은 달력 아래에서 펼쳐 볼 수 있다. 달력은 지난달부터 앞으로 12개월까지 조회하고, 한 달 전체를 인쇄할 수 있다.
- 신청을 열면 해당 주의 아토스 직원 일정이 잠기고, **총 필요 인원에서 아토스 직원 배정을 뺀 빈 슬롯만** 스태프에게 공개된다. 기본 근무 시간은 13:00–20:00, 필요 인원은 하루 1명이며 직원이 겹쳐 근무하는 날은 그 인원 이상으로 설정된다. 휴무는 필요 인원 0명이다.
- **요청 문구 복사**로 빈 날짜·시간·확정 방식을 복사해 각자에게 직접 전달한다. 첫 접속자는 구성원 관리에서 발급한 본인 전용 링크도 함께 전달한다. 시스템이 메시지를 보내지는 않는다.
- 스태프는 신청이 열린 빈 날짜에만 신청한다. 같은 날짜에 여러 명이 신청할 수 있으며 자동 또는 선착순 확정되지 않는다. 관리자는 신청자 중 배정하고 임시 저장한 뒤, **매주 월요일에 다음 주 근무표를 직접 확정**한다. 확정 전 임시 배정은 직원에게 보이지 않는다. 월요일 자동 확정이나 요일에 따른 확정 차단은 하지 않는다.
- 확정 전 **신청 닫고 직원 일정 수정**으로 직원 입력을 다시 받을 수 있다. 스태프 신청 내역은 보존되지만 앞으로의 임시 배정은 초기화된다. 직원 일정을 확인하고 다시 신청을 연다. 이미 작성된 이전 방식의 주간 기록은 기존 방식으로 유지되며 새 주부터 단계별 신청을 적용한다.
- 개인 링크는 해당 직원의 접속 권한이다. 재발급하면 기존 링크와 로그인 상태가 즉시 무효화된다. 확정된 주는 직접 수정할 수 없고 변경 요청을 관리자에게 남긴다. 근무 불가 승인은 해당 날짜의 확정 배정을 즉시 해제하므로 대체 인원을 배정하고 다시 확정해야 한다. 근무 가능 승인은 자동 배정하지 않는다.
- 직원은 본인의 입력·신청·확정 근무·변경 요청만 조회한다. 다른 직원의 이름과 신청 정보는 노출하지 않는다. 근무표 전용 비밀번호는 채용·사이트 관리 권한을 부여하지 않으며 채용 외부 조회용 계정은 근무표에 접근할 수 없다.
- 확정 근무가 남은 직원은 사용 중지할 수 없다. 확정 근무 이력이 있는 직원은 삭제 대신 사용 중지한다.

## 저장 및 배포

`workers/staff-schedule`의 `StaffSchedule` Durable Object가 `athoce-staff` 단일 인스턴스에 직원 및 구분, 월간 입력·신청, 주간 신청 단계·직원 배정·임시/확정 배정, 변경 요청을 저장한다. 트랜잭션과 버전 검증으로 중복 수정 덮어쓰기를 방지한다. 개인 링크 원문 대신 SHA-256 해시만 저장하고 브라우저는 HttpOnly/Secure 쿠키를 사용한다. 원문 링크는 관리자가 생성할 때 한 번 표시하며, 잃어버리면 재발급한다.

1. `npx wrangler deploy --config workers/staff-schedule/wrangler.jsonc`
2. Cloudflare Pages `athoce` production의 기존 `STAFF_SCHEDULE` 바인딩을 사용한다. `IMWEB_TOKEN_MANAGER`, `RECRUIT_RSVP`를 포함한 기존 바인딩과 환경변수를 보존한다.
3. Pages 소스 배포 후 직원/관리자 페이지와 API를 확인한다. 새 데이터 저장소이므로 기존 채용/면접 데이터와 분리된다.

검증: `node --test tests/*.test.mjs`, `npx wrangler pages functions build functions --outdir tmp/staff/pages-build`. 브라우저에서 날짜 선택, 같은 주 내 미저장 변경 유지, 배정 저장, 월 경계 및 모바일 달력을 확인한다.

전용 관리자 비밀번호는 Pages production 환경변수 `STAFF_ADMIN_PASSWORD_SHA256`에 SHA-256 해시만 설정한다. 전용 세션은 24시간 유효하며 비밀번호 해시 교체 시 기존 전용 세션이 즉시 무효화된다.
