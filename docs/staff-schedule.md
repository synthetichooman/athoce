# 직원 근무표

- 직원: `/staff/` (관리자가 발급한 개인 링크로 최초 접속)
- 관리자: `/staff/admin/` (근무표 전용 비밀번호 또는 사이트 소유자 관리자 계정)
- 구성원을 **운영진**(aategois·hooman·cementbay, 최대 3명)과 **스태프**로 구분한다. 먼저 운영진 3명을 등록하고, 각자의 개인 링크를 직접 전달한다. 기존 구성원은 기본적으로 스태프로 분류되며 관리 화면에서 구분을 변경할 수 있다. 신청 중이거나 확정된 주가 있으면 직원 구분 변경은 제한된다.
- 운영진은 매월 25일까지 다음 달에 실제 근무할 날짜를 입력한다. 반복 요일 또는 개별 날짜로 선택하며, 근무가 없어도 빈 날짜로 제출한다. 25일은 안내 기준이며 자동 제출 차단은 하지 않는다.
- 관리자는 월간 달력에서 날짜와 근무자 이름을 중심으로 확인한다. 토요일은 파랑, 일요일은 빨강이다. 점선 이름은 확정 전 배정이다. 필요·모집 인원 숫자는 표시하지 않는다. 날짜를 누르면 달력 아래 배정 메뉴가 열리고 운영진(at·ho·ce) 또는 스태프 한 명, 휴무를 직접 선택한다. 신청을 열지 않아도 직접 배정할 수 있다. 다른 신청자를 선택하면 이전 선택이 해제된다. 같은 주의 다른 날짜로 이동해도 작성 내용은 유지되며, 다른 주나 달로 이동할 때는 저장하지 않은 변경을 확인한다. 월간 현황은 전월 26일부터 선택한 달 25일까지 오늘을 넘지 않는 확정 스태프 근무를 요일별·급여 지급 주체별로 집계한다. 실제 출근 확인이나 급여 금액 계산은 하지 않는다.
- 선택한 날짜의 달력 아래 **스태프 신청 · 주간 확정**에서 운영진 3명의 입력 현황과 자동 반영된 근무일을 확인한다. 신청 열기·닫기, 근무 시간 변경, 최종 확정은 표시된 한 주 전체에 적용된다. 해당 주에 걸친 모든 달의 입력을 3명 모두 완료해야 **스태프 신청 열기**가 가능하다. 월 경계 주는 양쪽 달을 모두 입력해야 한다. 모든 배정·주간 확정·구성원 관리·변경 요청·월간 현황은 달력 아래에서 펼쳐 볼 수 있다. 달력은 지난달부터 앞으로 12개월까지 조회하고, 한 달 전체를 인쇄할 수 있다.
- 신청을 열면 해당 주의 운영진 일정이 잠기고, **운영진이 근무하지 않는 날짜만** 스태프에게 공개된다. 기본 근무 시간은 13:00–20:00, 하루 한 명 근무를 기본으로 하며 인원 설정 UI는 제공하지 않는다. 운영진이 직접 입력한 중복 근무 일정은 유지한다.
- **요청 문구 복사**로 빈 날짜·시간·확정 방식을 복사해 각자에게 직접 전달한다. 첫 접속자는 구성원 관리에서 발급한 본인 전용 링크도 함께 전달한다. 시스템이 메시지를 보내지는 않는다.
- 스태프는 신청이 열린 빈 날짜에만 신청한다. 같은 날짜에 여러 명이 신청할 수 있으며 자동 또는 선착순 확정되지 않는다. 관리자는 신청자 중 배정하고 임시 저장한 뒤, **매주 월요일에 다음 주 근무표를 직접 확정**한다. 확정 전 임시 배정은 직원에게 보이지 않는다. 월요일 자동 확정이나 요일에 따른 확정 차단은 하지 않는다.
- 확정 전 **운영진 일정 다시 받기**로 운영진 입력을 다시 받을 수 있다. 스태프 신청 내역은 보존되지만 앞으로의 임시 배정은 초기화된다. 직원 일정을 확인하고 다시 신청을 연다. 이미 작성된 이전 방식의 주간 기록은 기존 방식으로 유지되며 새 주부터 단계별 신청을 적용한다.
- 개인 링크는 해당 직원의 접속 권한이다. 재발급하면 기존 링크와 로그인 상태가 즉시 무효화된다. 확정된 주는 직접 수정할 수 없고 변경 요청을 관리자에게 남긴다. 근무 불가 승인은 해당 날짜의 확정 배정을 즉시 해제하므로 대체 인원을 배정하고 다시 확정해야 한다. 근무 가능 승인은 자동 배정하지 않는다.
- 직원은 본인의 입력·신청·확정 근무·변경 요청만 조회한다. 다른 직원의 이름과 신청 정보는 노출하지 않는다. 근무표 전용 비밀번호는 채용·사이트 관리 권한을 부여하지 않으며 채용 외부 조회용 계정은 근무표에 접근할 수 없다.
- 확정 근무가 남은 직원은 사용 중지할 수 없다. 확정 근무 이력이 있는 직원은 삭제 대신 사용 중지한다.

## 저장 및 배포

`workers/staff-schedule`의 `StaffSchedule` Durable Object가 `athoce-staff` 단일 인스턴스에 직원 및 구분, 월간 입력·신청, 주간 신청 단계·직원 배정·임시/확정 배정, 변경 요청을 저장한다. 트랜잭션과 버전 검증으로 중복 수정 덮어쓰기를 방지한다. 개인 링크 원문 대신 SHA-256 해시만 저장하고 브라우저는 HttpOnly/Secure 쿠키를 사용한다. 원문 링크는 관리자가 생성할 때 한 번 표시하며, 잃어버리면 재발급한다.

1. `npx wrangler deploy --config workers/staff-schedule/wrangler.jsonc`
2. Cloudflare Pages `athoce` production의 기존 `STAFF_SCHEDULE` 바인딩을 사용한다. `IMWEB_TOKEN_MANAGER`, `RECRUIT_RSVP`를 포함한 기존 바인딩과 환경변수를 보존한다.
3. Pages 소스 배포 후 직원/관리자 페이지와 API를 확인한다. 새 데이터 저장소이므로 기존 채용/면접 데이터와 분리된다.

검증: `node --test tests/*.test.mjs`, `npx wrangler pages functions build functions --outdir tmp/staff/pages-build`. 브라우저에서 날짜 선택, 같은 주 내 미저장 변경 유지, 배정 저장, 월 경계 및 모바일 달력을 확인한다.

전용 관리자 비밀번호는 Pages production 환경변수 `STAFF_ADMIN_PASSWORD_SHA256`에 SHA-256 해시만 설정한다. 전용 세션은 24시간 유효하며 비밀번호 해시 교체 시 기존 전용 세션이 즉시 무효화된다.

## 근무별 급여 지급 설정

관리자 달력에서 날짜를 누른 뒤 **급여 지급**에서 스태프의 지급 주체를 `at`, `ho`, `ce`, `athoce` 중 선택한다. 선택 즉시 저장하며 주간 확정과 독립적으로 지난 확정 근무도 수정할 수 있다. 새 배정은 먼저 임시 저장해야 한다. 미지정으로 되돌릴 수 있으며 기존 근무에 지급 주체를 임의로 채우지 않는다. 임시 배정과 공개 중인 근무자가 다르면 각각 설정한다.

주간 기록의 `payers[날짜][직원ID]`에 저장한다. `payroll.save`는 주간 버전, 날짜와 소속 주, 스태프 구분, 저장된 임시/확정 배정을 검증하고 버전을 증가시킨다. 근무자·시간·신청 단계·확정 상태는 변경하지 않는다. 월간 현황은 확정 배정의 직원ID에 해당하는 설정만 집계하며 기존 미설정 근무는 `미지정`으로 센다. 지급 주체 정보는 관리자 전용이며 직원 API에는 반환하지 않는다.

`employee.rename`은 예상 기존 이름을 검증하고 이름만 변경한다. 직원 ID, 개인 링크, 근무 이력은 유지한다.

## 급여 관리

- `/staff/payroll/`에서 근무표 관리자와 같은 로그인으로 사용한다. 근무표 상단 **급여 관리**에서도 이동할 수 있다. 직원 링크로는 조회·수정할 수 없다.
- 선택 월의 지급일은 **25일**, 정산 기간은 **전월 26일~당월 25일**이다. 오늘까지의 공개 확정 스태프 근무만 기본 집계한다. 운영진은 제외하고 사용 중지한 스태프의 과거 근무는 유지한다. 실제 출근 기록 연동이나 송금 기능은 없다.
- 스태프별 시급과 하루 **무급** 휴게시간을 명시적으로 저장한다. 금액이나 휴게시간을 임의로 가정하지 않는다. 설정은 해당 급여 월에만 적용하며 **이전 달 시급 불러오기**는 설정하지 않은 스태프만 채운다.
- 기본 유급시간은 근무표 종료−시작−무급 휴게시간이며, 날짜별 유급 분과 지급 주체(at·ho·ce·athoce)를 수정할 수 있다. 시간 변경에는 사유가 필요하고 0분은 실제 미근무를 뜻한다. 지급 주체만 수정하면 기본시간 계산을 유지한다. 수정 시간은 **기본시간으로 되돌리기**로 해제한다. 시급×유급 분÷60을 근무 건별 원 단위 반올림한다.
- 지난 임시 배정과 공개 근무가 다르면 **미확정 근무 확인**에서 공개 근무 반영·임시 배정을 실제 근무로 반영·실제 미근무 중 선택하고 확인 사유를 남긴다. 원래 근무표를 변경하지 않고 정산에만 반영한다. 근무 확인 기록에서 다시 확인할 수 있으며 근무자나 시간이 바뀌면 확인을 다시 요구한다.
- 주휴수당·기타 수당·세금·보험료는 자동 계산하지 않는다. 스태프별 **수당·공제**에서 지급 주체별 합산 조정액과 사유를 입력한다. 양수는 추가 지급, 음수는 공제, 0원 저장은 해당 조정 삭제다. 별도 법정 수당과 공제 검토가 필요하다.
- 시급·휴게·지급 주체 미확인, 미확정 근무, 음수 지급액이 있으면 확정을 차단한다. 정산 종료일 이전과 종료일 당일 마지막 근무가 끝나기 전에도 확정하지 못한다. 날짜별 수정과 최종 확정은 저장 버전/근무표 버전을 검증해 동시 수정 덮어쓰기를 방지한다.
- **이번 급여 확정**에서 개인별·지급 주체별 최종 금액을 확인하고 확정한다. 근무·시급·시간 수정 사유·수당·공제를 독립된 스냅샷으로 보관해 이후 원본 변경에 영향받지 않는다. 확정된 달의 지급 주체 수정은 근무표에서도 막는다. 원본이 바뀌면 급여 화면에 표시한다.
- 정정하려면 사유를 입력해 **확정 취소 후 수정**한다. 이전 확정 기록과 취소 사유를 보관하며, 수정 후 재확정한다. CSV는 현재 보이는 검토/확정 상태의 근무별 금액·조정액·직원별 합계를 내려받는다. 급여 이력이 있는 직원은 삭제나 운영진 전환 대신 사용 중지한다.

저장은 기존 Durable Object의 `payrun:YYYY-MM`에 월별 설정·시간 수정·근무 확인·수당/공제·확정 스냅샷·변경 이력을 보관한다. 관리자 API `GET /api/staff/admin?payrun=YYYY-MM`, `POST /api/staff/admin`의 `payrun.*` 작업을 사용하며 인증·동일 출처 검증은 기존 근무표 관리자와 같다. 급여 내역은 직원 API에 반환하지 않는다. 2020년부터 다음 해까지 급여 월을 조회할 수 있어 근무표의 지난달 조회 제한에 영향받지 않는다.

## 근로계약 작성·서명·보관

- `/staff/contracts/`에서 근무표 관리자와 같은 비밀번호로 접속한다. 근무표·급여 관리 상단의 **근로계약** 메뉴로 이동한다. 직원별 계약서를 조회하고 초안을 여러 개 보관할 수 있다. 계약 당사자는 지급 주체 약자와 별도로 실제 고용주 상호·대표자·주소·연락처를 작성한다.
- **새 계약서 → 초안 저장 → 저장한 계약서 서명 요청** 순서다. 근로자 정보, 계약 기간, 장소·업무, 근로일별 시작·종료 시각, 휴게, 시간급·임금 구성·계산·지급 방법, 휴일·연차·사회보험을 작성한다. 종료일과 추가 합의 사항 외의 항목은 요청 시 필수다. 변동 근무도 합의한 근로일별 시간을 구체적으로 입력한다. 계약 시급을 급여 설정에 자동 반영하거나 기존 근무표로 계약 조건을 자동 변경하지 않는다.
- 고용주 또는 권한자가 직접 그린 서명이나 이름 입력 서명, 명시적 동의로 요청한다. 이후 원문은 수정할 수 없다. 수정이 필요하면 대기 중 요청을 사유와 함께 취소하고 **이 내용으로 새 계약**을 작성한다. 서명 완료 계약은 취소·덮어쓰지 않는다.
- 요청 시 본인에게 전달할 전용 링크와 별도 확인코드를 한 번 표시한다. 메시지·메일 자동 발송은 없다. 관리자가 본인에게 직접 전달하고 확인코드는 별도 경로로 알린다. 링크 재발급은 이전 링크 및 접속을 무효화하며 원문·기존 서명은 보존한다. 미서명 요청은 30일 후 만료된다. 서명 완료 후에는 같은 링크·코드로 사본을 계속 열 수 있다.
- 수신자는 `/staff/contract/#token=...`에서 확인코드로 접속한다. 링크 토큰은 즉시 주소창에서 제거하고 서버 접근 로그에 전송하지 않는다. 계약자 성명, 서명, 본인이 지정한 사본 수령 이메일과 전자서명·전자문서 수령 동의를 입력한다. 관리자·일반 직원 권한 대신 해당 계약 전용 세션으로만 조회·서명한다. 서명은 중복 제출해도 최초 기록을 유지한다.
- 양쪽 서명·서명 시각·동의 문구와 원문/서명 기록 SHA-256을 보관한다. 관리자와 수신자는 독립 실행되는 HTML 사본을 내려받거나 브라우저 인쇄로 PDF를 저장할 수 있다. 관리자는 서명 기록 JSON과 진행 이력도 확인한다. 서버 기록과 해시는 애플리케이션의 변경 방지·확인 수단이며, 공인 본인 확인·인증서 서명·독립 시점확인·변경 불가 외부 보관 서비스를 제공하는 것은 아니다.
- **서명 완료**와 **사본 전달 완료**를 구분한다. 관리자가 서명된 사본을 지정 이메일로 실제 전달한 뒤 전달 방법과 확인 체크를 저장한다. 이 버튼은 이메일을 발송하거나 수신을 검증하지 않는다. 서버 저장·다운로드 가능 상태만으로 교부가 끝났다고 표시하지 않는다. 수신자 이메일 자체도 인증하지 않는다.
- 계약 이력이 있는 직원은 삭제 대신 사용 중지한다. 기존 계약의 성명·정보는 당시 원문을 유지하며 직원명 변경이나 사용 중지에 따라 바뀌지 않는다. 원문·서명에 대한 자동 삭제나 법정 보존기간 자동 판정은 없으며 관리자가 내려받은 사본도 직접 보관·관리한다.

저장 키는 기존 Durable Object의 `contract:<UUID>`와 `contract-link:<토큰 SHA-256>`이다. 토큰 원문·확인코드 원문·세션 원문은 저장하지 않는다. 확인코드는 링크 해시와 함께 해시하며 5회 오입력 시 해당 링크를 10분 잠근다. 계약 세션은 HttpOnly/Secure/SameSite=Strict, `/api/staff/contract` 경로, 24시간 유효이며 계약별 최근 5개만 유지한다. 관리자 API는 `GET/POST /api/staff/admin/contracts`, 수신자는 `POST /api/staff/contract/login`, `GET/POST /api/staff/contract`, `POST /api/staff/contract/logout`을 사용한다. 모든 변경은 동일 출처 JSON 요청과 저장 버전을 검증한다. 문서 무결성 확인 실패 시 수신자 열람·서명을 차단한다.

## 통합 관리 탭 및 노무·보험

`/staff/admin/`이 통합 진입점이다. 근무표·급여·노무/보험·근로계약 화면을 같은 로그인 아래 탭으로 전환한다. 각 화면은 한 번만 생성하고 숨기는 방식으로 입력·선택·스크롤을 유지한다. 기존 `/staff/payroll/`, `/staff/contracts/`, `/staff/labor/` 주소는 해당 탭으로 연결한다. 저장 전 표시와 이탈 경고를 제공하며, 다른 탭에서 저장하면 관련 화면을 강제로 덮어쓰지 않고 수동 새로고침 안내를 표시한다. 로그인 만료 시 재로그인 후 작성 화면을 유지하고, 명시적 로그아웃은 모든 탭을 닫는다. 새로고침·브라우저 종료 뒤까지 초안을 저장하는 기능은 아니며 개인정보를 localStorage 등에 남기지 않는다.

노무·보험은 급여 확정과 별도의 **검토용 추정**이다. 근무표 배정이나 실제 출근 시간을 약정 소정근로시간으로 간주하지 않는다. 실제 사용자, 입사/마지막 재직일, 약정기간별 요일·유급시간·시급, 주휴일, 비교 대상 통상근로자 근무일을 먼저 입력한다. 날짜별 약정 변경도 사유와 함께 기록한다. 일 8시간·월~일 주 40시간을 넘는 소정시간은 지원 범위를 벗어나므로 저장하지 않는다. 미입력 약정기간은 0시간으로 단정하지 않는다.

- **주휴수당**: 25일 급여 기간(전월 26일~당월 25일)의 주휴일별로 7일 근로관계 유지, 직전 4주(입사 후 4주 미만은 해당 기간)의 주 15시간 평균, 관리자의 개근·출근간주 확인을 구분한다. 시간은 해당 기간 소정근로시간 / 통상근로자 근무일 수로 추정한다. 미래 주휴일·미확인 개근은 조건부 예상액으로 남기며 확정액과 합산 확정하지 않는다. 근로조건 변경으로 판단 근거가 달라지면 기존 개근 확인을 재확인하도록 표시한다.
- **시간 기준**: 달력 월 1일~말일의 60시간과 산정일 직전 4주 평균 주 15시간을 각각 표시한다. 두 기준과 25일 급여 정산 기간은 다르다.
- **퇴직급여 인정기간**: 선택 월 말일 또는 현재일/마지막 재직일 중 앞선 날에서 28일씩 역산해 주 15시간 이상 구간의 재직일수를 누계한다. 미달·미확인 기간을 분리한다. 동일 사용자와의 연속 근로관계에 대한 추정이며 휴직·휴업·재입사·사용자 변경·최종 1년 요건은 별도 확인한다.
- **보험**: 월별 일반 근로자 해당 여부, 당시 나이 구간·근로기간·65세 이전 계속가입, 소득과 보험별 신고 기준액, 취득월 부과, 사업장 규모와 실제 산재 요율을 입력한다. 국민연금·건강/장기요양·고용·산재를 각각 판단한다. 3개월 계속근로의 고용보험 예외와 국민연금 소득 예외를 구분한다. 입·퇴사월의 월 60시간 자격과 날짜별 변동 약정의 주간 고용보험 기준은 별도 확인으로 남긴다. 공단 확인 결과는 보험별 예외 판단과 근거로 기록할 수 있다. 정보 부족이나 미확인 요율은 0원이 아닌 미확인으로 표시한다. 2026년 요율만 계산하며 연도가 바뀌면 금액 추정을 중지한다.

수당 예상액은 급여에 자동 가산하지 않는다. 급여의 수당·공제에서 이미 반영한 금액과 중복되지 않도록 검토하고 직접 반영한다. 사업주 보험료는 근로자 급여 공제액이 아니다. 지원금·정산·특례 적용 전 추정이므로 실제 고지액과 다를 수 있다. 화면 하단에 고용노동부·국민연금공단·건강보험공단·고용24의 확인 근거를 둔다.

관리자 API `GET/POST /api/staff/admin/labor`를 사용한다. Durable Object `labor:profile:<직원ID>`, `labor:month:<직원ID>:YYYY-MM`, `labor:audit:<직원ID>:<UUID>`에 근로조건·월별 사실·변경 전후 이력을 저장한다. 급여 기간이 월을 걸쳐도 개근 기록은 주휴일의 달력 월에 저장한다. 모든 변경은 전체 입력 근거 해시와 저장 버전을 검증하고 기존 관리자 인증·동일 출처 제한·직렬 트랜잭션을 따른다. 근로 이력이 있는 직원은 삭제·운영진 전환 대신 사용 중지한다. 검토 JSON은 선택 직원의 근로조건·월별 사실·현재 계산 결과를 내려받는다.

`tests/staff-labor.test.mjs`는 60/15시간 경계값, 주휴 개근·근거 변경, 역산 인정기간, 입퇴사월/65세/3개월/소득 예외, 2026년 보험 요율·상하한과 미확인 금액, 권한·동시 수정·변경 이력·삭제 방지·월 경계 저장을 검증한다. 로컬 가상 직원으로 브라우저 저장과 탭 입력 보존을 확인하며 운영 직원의 계약·근로조건·보험 사실을 임의로 생성하지 않는다.

### 근무표 기준 급여·보험료 예상 (2026-11-01)

급여 및 노무·보험 탭 상단의 예상 영역은 `functions/_staff-forecast.js`에서 동일하게 계산합니다. 25일 지급 예상은 전월 26일~당월 25일, 월간 급여·보험료·총 인건비는 당월 1일~말일입니다. 보험료와 합치는 급여는 반드시 같은 달력 월 기준입니다.

- 저장된 최신 날짜별 배정(draft, 명시적 휴무 포함)을 우선하고 해당 날짜 draft가 없을 때 공개 근무를 사용합니다. 동일 날짜를 중복 합산하지 않습니다. 직원의 가능 요일·신청만으로는 계산하지 않습니다. 임시 배정·미래 근무 횟수와 상세 내역을 제공합니다.
- 급여 확정 기록이 있으면 해당 스냅샷의 날짜별 근무·기본급을 사용합니다. 과거 근무의 유효한 reconcile 선택도 존중합니다. 나머지 근무는 해당 지급 월의 시급·무급 휴게시간, 저장한 실제시간 정정을 적용합니다. 해당 월 설정이 없으면 이전에 저장한 마지막 설정을 예상에만 이어 사용하고 가정한 월을 표시합니다. 설정은 저장하거나 복사하지 않습니다. 시급·휴게시간·시간 오류는 미확정으로 남깁니다.
- 주휴는 실제 사용자·입사일·주휴일·비교 근무일이 필요합니다. 근무표를 소정근로시간으로 가정하여 직전 4주까지의 배정을 사용하고, 개근 등 요건 충족 시 금액을 표시합니다. 기존 약정시간 기반 주휴 보고와 별도이며 자동 가산하지 않습니다.
- 예상 보험료는 월간 배정 시간과 예상 세전 급여(조건부 주휴 포함)를 사용합니다. 실제 사용자·재직기간·나이·계속근로·사업장 요율·공단 예외 판단은 저장된 조회 월 정보를 적용합니다. 계속 재직하는 정상월의 연금·건강 부과 여부가 미입력이라면 정상 부과를 가정하며, 입·퇴사월은 미확정으로 남깁니다. 날짜별 변동 약정의 고용보험 주 15시간 판단 등은 기존 모델처럼 별도 확인합니다. 2026년 외 요율은 계산하지 않습니다.
- 신고 기준액·근로조건·급여 조정·확정 기록은 변경하지 않습니다. 수동 수당·공제·세금과 지원금·고지 정산은 예상 총액에 넣지 않습니다. 예상 기본급·주휴·보험 중 필요한 값이 없으면 전체 합계를 0원으로 만들지 않고 확인 필요로 표시합니다. 조회 결과에는 직원 접근 토큰이 포함되지 않습니다.

검증: `node --test tests/*.test.mjs` (미래/임시/휴무/중복 방지, 기간 경계와 다음 지급 월 시급, 미입력 정보, 근무표 기반 보험 시나리오와 신고액 보존, 확정 스냅샷·과거 확인, 읽기 전용 API 일치).
