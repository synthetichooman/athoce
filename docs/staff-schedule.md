# 직원 근무표

- 직원: `/staff/` (관리자가 발급한 개인 링크로 최초 접속)
- 관리자: `/staff/admin/` (사이트 소유자 관리자 계정만 허용)
- 직원은 매월 25일까지 다음 달 가능일을 입력하고 관리자는 매주 월요일에 다음 주 근무표를 확정한다. 기준일 안내이며 자동 확정이나 제출 차단은 하지 않는다.
- 직원 추가 후 표시되는 개인 링크를 직접 전달한다. 링크는 해당 직원의 접속 권한이므로 전달 범위를 제한한다. 재발급하면 기존 링크와 로그인 상태가 즉시 무효화된다.
- 월간 달력에서 날짜나 반복 요일을 선택하고 제출한다. 선택하지 않은 날짜는 근무 불가로 취급하며, 미제출과 빈 날짜 제출은 구분한다.
- 관리자는 주간 시작/종료 시각(기본 13:00–20:00), 날짜별 필요 인원(기본 1명, 휴무 0명), 가능 직원 중 배정을 입력한다. 임시 저장은 비공개이고 확정 버튼을 눌러야 직원에게 표시된다. 자동 배정과 알림 전송은 포함하지 않는다.
- 확정된 주의 가능일은 직접 수정할 수 없다. 직원의 변경 요청을 관리자가 승인/반려한다. 근무 불가 승인은 해당 날짜의 확정 배정을 즉시 해제하므로 대체 인원을 배정하고 다시 확정해야 한다. 근무 가능 승인은 자동 배정하지 않는다.
- 직원은 본인 가능일, 확정 근무, 변경 요청만 조회한다. 채용 외부 조회용 계정은 내부 근무표에 접근할 수 없다.
- 확정 근무가 남은 직원은 사용 중지할 수 없다. 확정 근무 이력이 있는 직원은 삭제 대신 사용 중지한다.

## 저장 및 배포

`workers/staff-schedule`의 `StaffSchedule` Durable Object가 `athoce-staff` 단일 인스턴스에 직원, 월간 가능일, 주간 임시/확정 배정, 변경 요청을 저장한다. 트랜잭션과 버전 검증으로 중복 수정 덮어쓰기를 방지한다. 개인 링크 원문 대신 SHA-256 해시만 저장하고 브라우저는 HttpOnly/Secure 쿠키를 사용한다. 원문 링크는 관리자가 생성할 때 한 번 표시하며, 잃어버리면 재발급한다.

1. `npx wrangler deploy --config workers/staff-schedule/wrangler.jsonc`
2. Cloudflare Pages `athoce` production에 새 namespace를 `STAFF_SCHEDULE`로 바인딩한다. 기존 `IMWEB_TOKEN_MANAGER`, `RECRUIT_RSVP` 바인딩을 보존한다.
3. Pages 소스 배포 후 직원/관리자 페이지와 API를 확인한다. 새 데이터 저장소이므로 기존 채용/면접 데이터와 분리된다.

검증: `node --test tests/staff-schedule.test.mjs`, `npx wrangler pages functions build functions --outdir tmp/staff/pages-build`.
